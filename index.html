Presentación KPI - Ticket promedio

Descripción General

Los reportes desarrollados en Power BI representan la capa de presentación del análisis del Indicador Mensual de Ticket Promedio de Ventas Totales por Canales Digitales (Página Web y Aplicación Móvil) para Falabella Perú.

Para fines académicos, la información utilizada corresponde a un caso ficticio, elaborado a partir de datos simulados generados mediante herramientas de inteligencia artificial, con el propósito de replicar un escenario realista de análisis de ventas digitales. Este caso fue desarrollado de manera grupal en el marco del Diplomado en Business Analytics.

Los reportes fueron diseñados con un enfoque ejecutivo, priorizando una interfaz intuitiva que facilite la exploración de la información y el análisis del indicador.

Principales características

  • Storytelling con datos: cada reporte sigue una secuencia lógica que facilita la comprensión del comportamiento del indicador.
  • Análisis descriptivo: los reportes incluyen indicadores como ticket promedio mensual, monto total de ventas y número de transacciones.
  • Filtros dinámicos: los usuarios pueden explorar la información aplicando filtros por fecha y canal digital (Página Web y Aplicación Móvil).

Impacto

Esta capa permite visualizar de manera clara el desempeño del ticket promedio de ventas digitales, facilitando la identificación de oportunidades para mejorar el valor promedio por transacción y apoyar la toma de decisiones basada en datos.

🏗️ Arquitectura

Arquitectura del Proyecto

El proyecto implementa una arquitectura moderna de datos con el fin de centralizar y optimizar la información proveniente de las operaciones de ventas digitales de Falabella Perú. El diseño integra en un único ecosistema los datos de negocio, mejora su transformación y calidad con flujos ETL escalables, y habilita su consulta de manera segura y flexible a través de Power BI.

🚀 Diagrama de Arquitectura

La arquitectura se organiza en las siguientes capas:

📁 Data Sources

La información se origina en archivos Excel y sistemas transaccionales. Estos insumos se incorporan al ecosistema mediante procesos manuales o parcialmente automatizados.

🗄️ Data

Toda la información se consolida en el almacén de datos, funcionando como repositorio centralizado. Además, se integran datos capturados desde aplicaciones desarrolladas con apoyo de Cursor

🧩 Application

La interacción con los usuarios se gestiona a través de aplicativo, que ofrece una interfaz intuitiva para la carga, modificación y consulta de datos.

🔄 ETL

Con Microsoft Fabric (Dataflows y Pipelines) se automatiza la ingesta y transformación de datos hacia el Data Warehouse. Se emplean Notebooks en Python para ejecutar validaciones y generar notificaciones.

🧱 Data Warehouse

Los datos procesados se almacenan en un Fabric Data Warehouse, diseñado para consolidar información y habilitar análisis avanzados con medidas DAX y dimensiones de negocio.

📊 Presentation

Los usuarios acceden a reportes dinámicos mediante Power BI, con dashboards interactivos que favorecen la toma de decisiones en tiempo real.

🔄 ETL

Capa ETL – Extracción, Transformación y Carga

Este sistema implementa un flujo de datos automatizado y eficiente, integrando múltiples capas tecnológicas dentro del ecosistema Microsoft. El objetivo es garantizar la correcta ingesta, transformación y disponibilidad de la información para apoyar el análisis del KPI de ticket promedio.

1
Origen de Datos

Los datos se originan en los sistemas de ventas digitales (Web y App), que almacenan transacciones de forma estructurada en la base de datos fuente.

2
Pipeline ETL – Microsoft Fabric Data Factory

La orquestación del proceso ETL se gestiona mediante Microsoft Fabric Data Factory. El pipeline extrae datos de las tablas transaccionales, aplica procesos de limpieza y estandarización mediante Dataflows, y carga la información transformada en el Fabric Data Warehouse.

3
Automatización con Notebooks en Python

Una vez finalizado el pipeline, se ejecuta un Notebook en Python que genera y envía por correo un reporte diario con indicadores clave: ticket promedio, volumen de transacciones, monto total vendido por canal.

4
Seguridad y Ejecución Programada

El flujo completo se ejecuta de forma segura y programada, utilizando credenciales protegidas y reglas de ejecución automática diaria, garantizando que Power BI cuente siempre con información actualizada.

Data Warehouse – Capa de Almacén de Datos

✅ Conclusiones

Conclusiones

  • El análisis del indicador de ticket promedio en los canales digitales de Falabella Perú evidencia una oportunidad de crecimiento en el valor de las transacciones. Al cierre de 2025 el indicador alcanza S/ 238.93, aún por debajo de la meta estratégica de S/ 250, lo que refleja un potencial de mejora en la monetización de las compras digitales.
  • El modelo de datos desarrollado permitió integrar información de ventas, clientes, productos, campañas y canales digitales, facilitando un análisis integral del desempeño comercial. Esta estructura asegura consistencia en el análisis y permite que distintos analistas trabajen sobre un mismo modelo de información.
  • El análisis comparativo entre 2024 y 2025 muestra una evolución positiva del ticket promedio en los canales digitales, pasando de S/ 202.70 a S/ 216.09, lo que representa un crecimiento interanual de 6.61% y evidencia una tendencia favorable en el gasto promedio de los clientes.
  • La implementación de la arquitectura de datos con Microsoft Fabric, el aplicativo web y Power BI convierte los datos en un activo estratégico que impulsa la innovación y la capacidad de respuesta de la organización, asegurando información siempre actualizada para la toma de decisiones.
  • Los resultados obtenidos permiten identificar categorías, campañas y segmentos de clientes que impulsan el crecimiento del ticket promedio, proporcionando información clave para diseñar estrategias comerciales orientadas a incrementar el valor por transacción y fortalecer los ingresos del canal digital.
